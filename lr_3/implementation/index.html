Реализация¶

Маршрутизация и сериализация¶

DefaultRouter подключает наборы представлений приложения library под префиксом /api/. Для справочников используются ModelViewSet и ModelSerializer. Подробная карточка книги включает вложенные карточки авторов, а карточка издательства — список его книг.

Операции, которые меняют несколько связанных записей, оформлены как отдельные действия DRF. Входные сериализаторы проверяют поля запроса и существование объектов по их идентификаторам. Логику изменения состояния выполняют функции из library/services.py.

При записи читателя сериализатор принимает идентификатор зала только на входе. Сервис в одной транзакции создаёт читателя и первую запись о закреплении.

class ReaderRegistrationSerializer(ReaderSerializer):
    reader_room = serializers.PrimaryKeyRelatedField(
        queryset=ReaderRoom.objects.all(),
        write_only=True
    )

    def create(self, validated_data):
        return register_reader(**validated_data)

Выдача, возврат и переводы¶

Выдача выполняется внутри transaction.atomic. В PostgreSQL вызовы select_for_update() блокируют строки читателя и экземпляра до завершения транзакции. Затем сервис проверяет действующее закрепление читателя, состояние экземпляра и наличие открытой выдачи. Проверка открытой выдачи выполняется после блокировки экземпляра.

if Loan.objects.filter(
    book_copy=book_copy,
    return_date__isnull=True
).exists():
    raise ValidationError("Экземпляр уже выдан")

return Loan.objects.create(
    reader=reader,
    book_copy=book_copy,
    issued_date=timezone.localdate()
)

При возврате сервис устанавливает return_date. Повторная выдача занятого экземпляра и повторный возврат дают ответ 400 Bad Request. При переводе читателя или экземпляра закрытие прежнего закрепления и открытие нового происходят в одной транзакции.

Текущая реализация допускает списание экземпляра с открытой выдачей. При этом дата возврата остаётся пустой, а книга исчезает из списка книг на руках, поскольку этот список исключает списанные экземпляры.

Аналитические запросы¶

Запрос Условие отбора
Книги на руках Открытые выдачи выбранного читателя по несписанным экземплярам. Результат содержит уникальные записи каталога.
Просрочившие возврат Есть открытая выдача с датой строго раньше даты месяц назад. Если в прошлом месяце такого числа нет, берётся последний день этого месяца.
Читатели с редкими книгами Есть открытая выдача несписанного экземпляра книги, у которой осталось не более двух несписанных экземпляров.
Читатели младше 20 лет Действующее закрепление за залом и возраст строго меньше 20 лет.
Статистика образования Среди читателей с действующим закреплением вычисляются доли по уровню образования. Доля читателей с учёной степенью считается отдельно. При пустой выборке все доли равны нулю.

При поиске редких книг Django ORM группирует экземпляры по книге и подсчитывает их количество.

rare_books = (
    BookCopy.objects
    .filter(scrapped_at__isnull=True)
    .values('book_id')
    .annotate(total=Count('id'))
    .filter(total__lte=2)
    .values('book_id')
)

Месячный отчёт¶

Отчёт формируется двумя агрегирующими запросами на день. Один подсчитывает уникальные экземпляры по залам, второй — уникальных читателей. В обоих учитываются закрепления, которые начались к выбранной дате и действовали в этот день.

Отдельная агрегация считает уникальных читателей по записям с причиной registration за месяц. Если читатель был записан в разные залы в течение одного месяца, в общем итоге он учитывается один раз, а в сводке — по одному разу для каждого зала, в который его записывали. Текущий месяц отображается по сегодняшний день включительно. Запрос за будущий месяц отклоняется.
