Модель данных¶

Сущности и связи¶

Модель Назначение и основные поля Связи
Author Автор, имя name many-to-many с книгами
Publisher Издательство, название name и описание description Одно издательство может выпускать много книг
Category Категория каталога, название name many-to-many с книгами
Book Запись каталога, название name, год издания year_of_publication, код code FK → Publisher, M2M → Author и Category
BookCopy Физический экземпляр, дата списания scrapped_at FK → Book
Reader Читатель, номер билета, ФИО, паспорт, дата рождения, адрес, телефон, образование, наличие учёной степени и дата последней регистрации Один читатель может иметь несколько выдач и записей истории
ReaderRoom Читальный зал, название name, номер number и вместимость capacity Один зал может фигурировать во многих записях истории
Loan Выдача экземпляра, даты выдачи issued_date и возврата return_date FK → Reader, FK → BookCopy
ReaderRoomHistory Период закрепления читателя за залом, даты начала и окончания, причина reason FK → Reader, FK → ReaderRoom
BookCopyRoomHistory Период нахождения экземпляра в зале, даты начала и окончания FK → BookCopy, FK → ReaderRoom

Аккаунты Django используются для входа в систему. У модели Reader нет связи с аккаунтом Django. Запись читателя заводит сотрудник библиотеки.

Ограничения¶

  • Уникальны код книги, название категории, номер зала и номер читательского билета. Уникальность паспорта проверяется по паре «серия и номер».
  • Серия паспорта содержит четыре цифры, номер — шесть. Год издания ограничен диапазоном от 1400 до 2026 включительно на уровне модели и базы данных.
  • Внешние ключи используют on_delete=models.PROTECT. Например, удалить читателя, на которого ссылается выдача, нельзя.
  • Открытая выдача имеет return_date = null. Значение scrapped_at = null означает, что экземпляр числится в фонде.

Хранение истории¶

Действующее закрепление имеет end_date = null. Перевод закрывает прежнюю запись и открывает новую с той же датой начала. При подсчёте за день дата начала включается в период, а дата окончания исключается. Например, если экземпляр переведён 12 ноября, в отчёте за этот день он учитывается в новом зале.

Причина registration отмечает первичную запись или запись ранее выписанного читателя. Причина transfer отмечает перевод между залами. Перерегистрация обновляет дату последней регистрации читателя и при необходимости номер билета, сохраняя действующее закрепление за залом.
